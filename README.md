# Raised

Charts in textbooks, checked and turned into data tables, descriptions, sound and tactile graphics for blind and low-vision students.

Live demo: https://m-simakhov--raised-web.us-east.modal.run · Benchmark: https://m-simakhov--raised-web.us-east.modal.run/bench

Built with NVIDIA Nemotron 3.5 Super VL, Nemotron 3 Ultra and Nemotron 3.5 Lightning on Nebius Token Factory.

## The problem

Teachers of visually impaired students and braille transcribers currently spend a significant amount of time preparing textbook material. A common task is manually redrawing charts from PDF textbooks as tactile graphics. This process involves translating data into a format suitable for braille embossers or swell paper, requiring considerable manual effort.

## What it does

Raised is a tool designed to automate the creation of tactile graphics and braille text files from textbook charts. It takes a textbook chapter as a PDF or a single chart image as input. The system then generates five outputs for each chart: a checked data table, a long description with a short alt text, an explorer interface, a tactile graphic, and a braille text file (BRF). Each output is initially labelled as a draft for review by the transcriber.

## Why it checks its own reading

Raised incorporates a double-checking process to mitigate the potential for errors from the vision model. A primary step involves using NVIDIA Nemotron 3.5 Super VL to interpret the chart’s meaning and extract initial values for each point. Simultaneously, a separate code-based process performs Optical Character Recognition (OCR) to identify tick labels, fit the axis scale, and measure lines, bars, and points based on their colour.

If the two readings diverge, both are redrawn over the original chart. The reading that most closely matches the pixel data determines the correct value. Any points where the readings disagree are flagged for review. NVIDIA Nemotron 3.5 Super VL then performs a secondary comparison, listing any discrepancies.

## How each model is used

NVIDIA Nemotron 3.5 Super VL is used for initial data interpretation. NVIDIA Nemotron 3 Ultra generates the long description, checking the book’s caption and text against the data to identify potential misinterpretations, such as incorrect descriptions of changes (e.g., “doubled” when the data shows a smaller rise). NVIDIA Nemotron 3.5 Lightning shortens long labels to fit within braille constraints and creates the short alt text.

The code component performs rigorous numerical checks, verifying every number in every generated sentence against the underlying data table and computed facts. Any sentence with an unverified number is regenerated and then removed. All model calls are executed on the Nebius Token Factory. The application itself runs on CPU.

## Safety and honesty

Every output generated by Raised is labelled as a draft. This is crucial for ensuring accuracy. Any uncertainty identified during the process is flagged for review by the transcriber before the results can be exported. This layered approach prioritises accuracy and allows for human intervention where necessary.

## Prior work

Raised builds upon previous research in automated tactile graphics generation. Key influences include:

*   MAIDR (multimodal access to charts from data, by the xability lab at the University of Illinois)
*   The Tactile Graphics Assistant from the University of Washington
*   DePlot (Google Research, 2022) for chart-to-table reading and its table metric.

## Limits

Raised currently supports line, bar, horizontal bar, and scatter charts. Pie charts, stacked bars, maps, and diagrams are not supported. Heavily decorated or 3D charts may be flagged for manual review rather than automated processing. The tactile output adheres to published guidelines from the Braille Authority of North America’s Guidelines and Standards for Tactile Graphics (2010) but has not undergone review by a certified transcriber. It is not intended as a substitute for a human transcriber’s expertise.

Measured results: On 300 synthetic charts with known values, pixel measurement alone reads values with a median error of 0.24% of the axis range. Results with the vision model on real published charts are added on the benchmark page once run. Uploads are processed in memory and not stored; results are kept for 24 hours so they can be downloaded.

## Run it

```bash
python3.12 -m venv .venv && .venv/bin/pip install fastapi[standard] pillow numpy scipy matplotlib pypdfium2 pytesseract shapely cairosvg pytest
brew install tesseract liblouis cairo          # Debian: apt install tesseract-ocr liblouis-bin libcairo2
export NEBIUS_API_KEY=...                       # omit to serve recorded samples
.venv/bin/python local.py                       # http://localhost:8790
.venv/bin/python -m pytest tests
```

Benchmark: `python -m bench.make_synth --split bench --n 300 --seed 1`, then `python -m bench.run --config pixel_only --split synth-bench`.

Deploy: `modal secret create raised NEBIUS_API_KEY=... && modal deploy app.py`.
